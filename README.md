# 関東・日当たりチェッカー

築古不動産（ボロリッチ／築福不動産）の配布特典。
航空写真の上で家と周りの建物をタップすると、冬至にその窓へ何時間日が入るかを計算します。

- 公開URL: https://satokott4274-blip.github.io/bororich-hiatari/
- 単一HTML・依存ライブラリなし（Google Fontsのみ外部）
- **デザインは物件診断シミュレーター（bororich-shindan-app）と共通**。配色トークン・ロゴ・街並みシルエット・stepCard・判定スタンプ・ctaCard を移植しているので、片方のデザインを変えたらもう片方も合わせること

## なぜ「建物を人がタップする」方式なのか

shademap.app のように自動で影を出すには建物の高さデータが要るが、OSMの実測では：

| 地域 | 建物ポリゴン | 高さデータあり |
|---|---|---|
| 新宿駅周辺 | 887件 | 257件（29%） |
| 世田谷の住宅街 | 2,416件 | 672件（28%） |
| 牛久市岡見町 | 2件 | 0件（0%） |

築古物件のある郊外ではデータが存在せず、都心でも7割が欠ける。
高さの無い建物は影を落とさないので、**日当たりを奪っている隣家がデータに無いまま「日当たり良好」と表示される**事故が起きる。
そこで、データベースに無い高さを人間が入れる方式にした。

## 地図の見せ方（shademap.app 準拠）

- 影は building ごとの図形ではなく **1枚のフラットな面**（`<g opacity>` でまとめるので重なっても濃くならない）。日が回らない時間帯は画面全体を沈める。
- 建物は塗らず白い輪郭だけ。影を主役にする。
- 太陽は地図の縁に置き、家まで光線を引く（当たっていれば金の実線／遮られていれば灰の破線）。「どの方向から差し込むか」が一目でわかる。
- 時刻スライダーの溝そのものが1日のタイムライン（金＝日が入る／灰＝影／淡＝窓の裏・夜）。shademap の時刻ルーラーに、こちらは「いつ日が入るか」の情報を載せている。
- 「▶1日を再生」で日の出→日の入りを8秒で掃く。`setInterval` の時間駆動（`requestAnimationFrame` は背景タブで止まる）。
- 航空写真タイルは z18 が上限なので、z19 は z18 タイルを2倍描画して出している（`TILEMAX`）。家を置いた時点で自動的に z19 まで寄せる。

## 操作まわりの作り

- **タップ判定は最低44px四方**（`Math.max(22,(w/2)/mpp)`）。指で押せる大きさの下限。
- **建物のタップは「選択」**。削除はリストの✕だけ。以前は再タップで削除していたが、2棟目を隣に置こうとして1棟目を消す事故が起きる。
- **ピンチズーム対応**（pointerイベントを Map で複数管理）。指の中間にある地点を固定したまま拡大縮小する。ズームは16〜19.6の連続値で、ピンチ中はタイルにCSS transformでscaleを当て、指を離した時点で再ラスタライズする。`setPointerCapture` は端末により例外を投げるので、指の登録を先にして try/catch で囲む（囲まないと2本目の指が登録されずピンチが死ぬ）。
- **ひとつ戻す**（履歴40件）と**全部消すの確認ダイアログ**。
- **localStorage に自動保存**（キー `bororich-hiatari-v1`）。地点・ズーム・レイヤー・家・建物・窓の向き・階・季節を保存し、次回は「前回の続きを表示しています」と出す。「最初から」で消去。プライベートモードでの失敗は try/catch で握りつぶす。デモ中は保存しない。

## 使い方デモ

地図タブ先頭の「▶ 使い方デモを見る（約50秒）」で、10ステップを自動再生する。画面下固定の字幕バーで解説し、「やめる」でいつでも中断できる。

**舞台は東京都世田谷区桜新町。家・南どなり・南西どなりの座標は OpenStreetMap の実在の建物の中心から採っている**ので、置いた四角が航空写真の屋根にぴったり乗る。目分量で決めると道路の上に建物が乗って一気に嘘くさくなる。

筋書き（数字がすべての段で動くように配置を選んである）:
- ② 南どなりを2階建てで置く → **8時間38分**（13.6m 先の2階建ては冬でも影を落とさない）
- ③ 実は3階建てだった → **6時間39分**。10:29〜12:28 の真昼だけ影に沈む
- ④ 再生でその影の出入りを見せる
- ⑤ 南西にもう1棟 → **3時間42分**

補足：建物の**手前の面**が窓に近いと、2階建てでも3階建てでも等しく遮るので階数を変えても数字が動かない（物理的には正しい）。デモで階数の効果を見せるには、手前の面が9m以上離れた配置を選ぶ必要がある。

## 計算の前提## 計算の前提

- 太陽位置：NOAA の計算式を自前実装。東京の冬至（日の出06:47／日の入16:32／南中高度30.87°）夏至（04:26／19:01）で国立天文台の値と一致。
- 遮蔽判定：窓から太陽へ向かう光線が、建物の高さに達するまでの区間で建物フットプリントと交差するかを見る（軸並行正方形とのスラブ法）。
- 地図モデルと手入力モデルは独立実装だが、同条件で日照252分・時間帯まで完全一致することを確認済み。
- 太陽高度5度以下は日照に数えない（周囲の家・塀・樹木に必ず遮られるため）。
- 8方位比較で真南が不利に出るのは仕様。太陽が最も高い時間に建物が正面にあるため。
